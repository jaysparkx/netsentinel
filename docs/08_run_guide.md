# 08 — دليل التشغيل والعرض

> النسخة المختصرة خطوة بخطوة موجودة في **[`run.txt`](../run.txt)** في المجلد الرئيسي. هذا الملف يشرح **لماذا** كل خطوة.

## 1. ما الذي نشغّله بالضبط؟

```
 ┌───────────── اللابتوب ─────────────────────────────────────────┐
 │                                                                  │
 │  Terminal:  sudo .venv/bin/netsentinel web                       │
 │      │                                                           │
 │      ▼                                                           │
 │  خادم بايثون (FastAPI) على http://127.0.0.1:8000                │
 │      ├─ يحمّل النماذج المدرَّبة من artifacts/                    │
 │      ├─ يقرأ الحزم من كرت الشبكة (Scapy) ← لهذا يحتاج sudo       │
 │      ├─ يشغّل "ميدان الهجوم": خادم ضحية على 8088 + nmap + flood │
 │      └─ يرسل النتائج للمتصفّح لحظة بلحظة (SSE)                  │
 │      │                                                           │
 │      ▼                                                           │
 │  المتصفّح: الموقع (HTML + CSS + JavaScript، بدون إنترنت)        │
 └──────────────────────────────────────────────────────────────────┘
```

- **لا إنترنت مطلوب:** الخطوط والمكتبات كلها داخل المشروع.
- **لا تدريب مطلوب:** النماذج المدرَّبة محفوظة في `artifacts/` (37 MB).
- **لماذا sudo؟** نظام macOS لا يسمح لأي برنامج بقراءة حزم الشبكة إلا بصلاحيات المدير. بدون sudo يعمل كل الموقع ما عدا مفتاح Monitoring.

## 4. العرض الحي — كيف يعمل "ميدان الهجوم"؟

المشكلة: في قاعة العرض لا تحدث هجمات حقيقية صدفة، فالمراقبة الحية ستُظهر "لا شيء".
الحل: نصنع **مهاجماً وضحية على نفس اللابتوب** ونراقب بينهما:

```
   ┌──────────── اللابتوب (127.0.0.1 فقط) ────────────┐
   │   خادم ويب "ضحية" :8088  ◄── تصفّح طبيعي (مفتاح)   │
   │                          ◄── nmap / flood (أزرار)  │
   │   NetSentinel يراقب الواجهة lo0 ويحكم على كل اتصال  │
   └───────────────────────────────────────────────────┘
```

| الهجوم | الأداة الحقيقية | ماذا يحدث | ماذا نتوقّع من النظام |
|---|---|---|---|
| `scan` | `nmap -sS -p 1-2000,8088` | 2001 محاولة اتصال بمنافذ مختلفة خلال ثانية | **Probe** — المصنِّف يعرف هذا النمط |
| `service-scan` | `nmap -sT -sV --top-ports 100` | يتصل بالمنافذ ويسأل كل خدمة عن اسمها وإصدارها | Probe أو Unknown-Anomaly |
| `flood` | 100 خيط بايثون، 3000 طلب | إغراق خادم الويب بطلبات كاملة وصحيحة | **Unknown-Anomaly** — المصنِّف لم يرَ هذا قط، الـ Autoencoder يلتقطه |

### 🔒 الأمان (نقطة مهمة لمشروع أمن سيبراني)
1. **الهدف ثابت في الكود** (`127.0.0.1`) — لا يمكن تغييره من الموقع، فلا يمكن استخدام الموقع لمهاجمة أحد.
2. **الطرفية في الموقع ليست طرفية حقيقية:** تقبل فقط 8 أوامر محدّدة. لماذا؟ الخادم يعمل بصلاحيات root، ولو قبلنا أي نص لأصبح الموقع ثغرة **تنفيذ أوامر عن بُعد (RCE)** — أخطر أنواع الثغرات. جرّبنا `rm -rf /` ← "command not allowed".
3. **أوامر الهجوم تُقبل فقط من نفس الجهاز** — حتى لو شُغّل الخادم على عنوان شبكة.
4. الخادم يستمع على `127.0.0.1` فقط افتراضياً — لا يراه أحد في الشبكة.

## 5. أخطاء اكتشفناها أثناء العرض الحي (وأصلحناها)

هذه دروس هندسية حقيقية — يمكن ذكرها للّجنة:

| ماذا حدث | السبب | الإصلاح |
|---|---|---|
| توقّف الالتقاط الحي فجأة أثناء الـ flood | Scapy حاول تحليل محتوى إحدى الحزم بعمق فانهار (`maximum recursion depth`) | نطلب من Scapy فكّ الترويسات فقط (IP/TCP/UDP/ICMP) — أسرع وأأمن، ولا نحتاج المحتوى أصلاً |
| الطرفية امتلأت برسائل خطأ مخيفة | خادم الضحية يطبع خطأً لكل طلب قطعه المهاجم (`BrokenPipe`) — وهذا طبيعي تحت الإغراق | نتجاهل هذه الأخطاء المتوقّعة فقط |
| الخادم "علق" عند إعادة التشغيل | ينتظر إغلاق البثّ المباشر للصفحات المفتوحة إلى الأبد | مهلة إغلاق ثانيتان |
| المراقبة الحية رأت ~8% فقط من مسح nmap والـ flood | كنا نلتقط 3 ثوانٍ ثم نحلّل، وأثناء التحليل لا أحد يستمع — فضاعت الحزم التي وصلت في "الفجوة" | خيطان: واحد يستمع دون توقّف، وآخر يحلّل كل 3 ثوانٍ. اختبار آلي يرسل 2000 حزمة دفعة واحدة ويتأكّد أنها كلها وصلت |
| حتى بعد الإصلاح السابق، ضاع أغلب مسح nmap | مخزن الالتقاط في نواة macOS كان 64 KB (~800 حزمة)، والمسح ~4000 حزمة في ثانية — فأسقطتها النواة | تكبير المخزن إلى الحدّ الأقصى (512 KB)، مع إجبار Scapy على قراءته كاملاً (شرط في macOS) + اختبار آلي |
| ظهر الملف نفسه يُقرأ 3 مرات عند البدء | 3 طلبات وصلت معاً قبل انتهاء الأول | قفل + تخزين النتيجة على القرص ← التحليل أصبح 0.1 ثانية بدل 20 |

## 7. أوامر الطرفية (بدون الموقع)

| الهدف | الأمر |
|---|---|
| الاختبارات | `.venv/bin/pytest -q` |
| تنزيل البيانات | `.venv/bin/netsentinel download --dataset all` |
| تدريب NSL-KDD | `.venv/bin/netsentinel train` |
| تدريب CIC-IDS2017 | `.venv/bin/netsentinel train --dataset cicids2017` |
| تحليل pcap | `.venv/bin/netsentinel pcap data/real/real_attack.pcap` |
| مراقبة حية في الطرفية | `sudo .venv/bin/netsentinel live --iface lo0` |
| التقاط حزم حقيقية جديدة | `sudo bash tools/capture_real_traffic.sh` |
| تعليم النظام "طبيعي" جهازك | `.venv/bin/netsentinel baseline data/real/real_normal.pcap` |
