================================================================================
‏NetSentinel - طريقة التشغيل والاستخدام
================================================================================

‏كل سطر يبدأ بعلامة $ هو أمر: انسخه بدون علامة $ والصقه في Terminal ثم اضغط Enter.
‏لفتح Terminal على الماك: اضغط Cmd + Space واكتب Terminal ثم Enter.

‏الأوامر هنا تفترض أن مجلد المشروع على سطح المكتب (Desktop).
‏إذا وضعته في مكان آخر، غيّر مسار أمر cd.


================================================================================
‏الجزء 1 - التثبيت على لابتوب جديد (مرة واحدة، حوالي 10 دقائق، يحتاج إنترنت)
================================================================================

‏1) ثبّت Homebrew (مدير البرامج للماك) إذا لم يكن مثبتاً:

$ /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

‏2) ثبّت nmap و uv (مدير بايثون سريع):

$ brew install nmap uv

‏3) ادخل مجلد المشروع:

$ cd ~/Desktop/netsentinel

‏أو نزّل المشروع من GitHub بدل نسخ المجلد:

$ git clone https://github.com/jaysparkx/netsentinel.git ~/Desktop/netsentinel

‏4) أنشئ بيئة بايثون وثبّت المكتبات:

$ uv venv --python 3.11 .venv
$ uv pip install --python .venv/bin/python -e ".[live,web,dev]"

‏5) تأكد أن كل شيء يعمل (يجب أن ترى: 38 passed):

$ .venv/bin/pytest -q

‏انتهى. النماذج المدرّبة موجودة داخل المشروع في مجلد artifacts، فلا تحتاج تدريباً.


================================================================================
‏الجزء 2 - تشغيل الموقع
================================================================================

‏ادخل مجلد المشروع أولاً (في كل مرة تفتح فيها Terminal جديداً):

$ cd ~/Desktop/netsentinel

‏الطريقة أ: التشغيل الكامل مع الكشف الحي (هذه للعرض أمام اللجنة):

$ sudo .venv/bin/netsentinel web

‏- سيطلب Password: اكتب كلمة مرور الماك ثم Enter. لن تظهر أي حروف وأنت تكتب، وهذا طبيعي.
‏- لماذا sudo؟ لأن قراءة كرت الشبكة تحتاج صلاحيات المدير.
‏- يفتح المتصفح تلقائياً على العنوان: http://127.0.0.1:8000

‏الطريقة ب: بدون كلمة مرور (كل شيء يعمل ما عدا الالتقاط الحي، والإعادة Replay تعمل):

$ .venv/bin/netsentinel web

‏مهم جداً:
‏- لا تغلق نافذة Terminal أثناء العرض، لأن إغلاقها يطفئ الموقع.
‏- لا تضغط Ctrl+C داخلها، لأنها تطفئ الموقع أيضاً.
‏- الموقع لا يحتاج إنترنت.

‏للإيقاف في النهاية: اضغط داخل نافذة Terminal ثم Ctrl + C، أو أغلق النافذة.


================================================================================
‏الجزء 3 - كيف تستخدم الموقع (القائمة في أعلى الصفحة)
================================================================================

‏قسم Monitor (المراقبة، أول الصفحة):
‏- اختر Replay a capture وملف real_attack والسرعة ثم اضغط Start: يُعاد بث حزم حقيقية التقطناها بتوقيتها الأصلي.
‏- أو اختر Live interface لمراقبة الحركة الحية الآن (يحتاج الطريقة أ). في القائمة خياران:
‏  - Network (en0): شبكة الواي فاي الحقيقية، أي ما يدخل ويخرج من اللابتوب إلى الإنترنت.
‏  - This computer only (lo0): حركة اللابتوب مع نفسه فقط. هنا تظهر هجمات ميدان الهجوم، وأيضاً برامج الجهاز (Docker وخوادم التطوير) لذلك تظهر إنذارات كاذبة منها.
‏- قبل المراقبة الأولى على en0 اضغط Learn normal traffic واستخدم الإنترنت بشكل عادي دقيقتين (تصفح، يوتيوب). النظام يسجل الحركة ويعيد تدريب الـ Autoencoder عليها، فيتعلم شكل "الطبيعي" في شبكتك ويقل الإنذار الكاذب.
‏- ملاحظة: Learn يدرب الطبقة الثانية فقط. المصنف ما زال من بيانات NSL-KDD، فقد يسمي بعض الاتصالات الحديثة DoS خطأً.
‏- Status: الحالة بكلمات بسيطة من آخر 20 دفعة: Quiet (لا تنبيهات)، Watch (تنبيهات قليلة)، Being scanned (مسح منافذ)، Under attack (هجوم معروف أو شذوذ كثير). تحتها خط يبين نسبة الاتصالات المشبوهة في كل دفعة.
‏- العدادات: الاتصالات، متوسط الاتصالات في الدفعة، المشبوه، المسح، الشذوذ غير المعروف.
‏- Connections per batch: عمود لكل دفعة ملون حسب القرار. مرّر الفأرة على العمود لترى الأرقام.
‏- Which model caught it: كم تنبيهاً سمّاه المصنف، وكم كشفه الـ Autoencoder وحده. هذا الرقم الثاني هو ما كان سيضيع بدون الطبقة الثانية، وهو فكرة المشروع.
‏- Autoencoder score: توزيع خطأ إعادة البناء لكل اتصال، والخط المتقطع هو العتبة. ما على يمين الخط يعتبره الـ Autoencoder غريباً.
‏- Destination ports touched: المنافذ من 0 إلى 65535. التصفح العادي خطوط قليلة، ومسح nmap يظهر كشريط عريض.
‏- Conversations: كل مصدر وهدف في سطر واحد: عدد الاتصالات، عدد المنافذ، المشبوه منها، ونوعها الغالب.
‏- Incidents: أحدث حادثة في الأعلى مع وقتها وسببها.

‏قسم Results (النتائج):
‏- اختر التجربة من الأزرار، وابدأ بـ cicids2017_temporal لأنها الأهم.
‏- ثم اختر ملف الاختبار من قائمة Test set.
‏- في الأعلى أربعة أرقام: الكشف، الإنذار الكاذب، الهجمات الجديدة، الدقة، وتحت كل رقم الفرق عن المصنف وحده.
‏- تحتها رسوم تفاعلية (مرّر الفأرة لترى الأرقام): الكشف لكل فئة، مصفوفة الالتباس (بدّل بين classifier و autoencoder و hybrid)، اختيار العتبة، الهجمات الجديدة، اختيار النموذج، وأهم الميزات.
‏- بعدها اختر cicids2017_random وقارن: 99.7%، واشرح لماذا هذا الرقم مضلل.

‏قسم Analysis (تحليل ملف كامل):
‏- اضغط على real_attack.pcap، أو ارفع أي ملف pcap من Wireshark.
‏- يظهر: العدادات، الخط الزمني للملف، جدول Conversations، ثم الحوادث وفي كل حادثة المهاجم والهدف ونوع الهجوم وسبب القرار.

‏ميدان الهجوم Attack range (أسفل قسم Monitor):
‏- مفتاح Normal browsing: مستخدم وهمي يتصفح بشكل طبيعي.
‏- مفتاح Attack mode: الهجمات تعمل تلقائياً واحدة بعد الأخرى.
‏- الطرفية: اكتب أمراً واضغط Enter، أو اضغط الأزرار.

‏أوامر الطرفية:
‏- الأمر scan: مسح منافذ حقيقي بـ nmap
‏- الأمر service-scan: مسح الخدمات وإصداراتها
‏- الأمر flood: إغراق HTTP بـ 3000 طلب
‏- الأمر auto on أو auto off: الهجوم التلقائي
‏- الأمر browse on أو browse off: التصفح الطبيعي
‏- الأمر status: ماذا يعمل الآن
‏- الأمر help: قائمة الأوامر
‏- الأمر clear: مسح الشاشة

‏الطرفية لا تقبل إلا هذه الأوامر، وكل الهجمات على هذا اللابتوب فقط (127.0.0.1).
‏التنبيهات تظهر في الطرفية كسطر يبدأ بـ [ALERT].

‏قسم Lab (تجربة اتصال واحد):
‏- اضغط normal web أو SYN flood أو port scan لتعبئة القيم.
‏- غيّر أي رقم واضغط Check، فيظهر القرار والسبب.
‏- تجربة للجنة: من normal web اجعل serror_rate تساوي 1 و count تساوي 300.


================================================================================
‏الجزء 4 - سيناريو العرض أمام اللجنة (10 دقائق)
================================================================================

‏قبل دخول القاعة شغّل الموقع واتركه مفتوحاً على قسم Monitor:

$ cd ~/Desktop/netsentinel
$ sudo .venv/bin/netsentinel web

‏1. دقيقة - المشكلة: "نموذج واحد لا يرى الهجوم الجديد". انظر docs/00_start_here.md
‏2. دقيقة - الفكرة: "نموذجان: مصنف يعرف الهجمات، وكاشف يعرف الطبيعي فقط".
‏3. دقيقة - قسم Monitor: Replay لملف real_attack، وقل "هذه حزم حقيقية من لابتوبنا". أشر إلى الحالة حين تصبح Under attack، وإلى شريط المنافذ أثناء المسح.
‏4. دقيقتان - قسم Results: temporal ثم random. "99.7% مقابل 62.5%، وهذا اكتشافنا".
‏5. ثلاث دقائق - قسم Monitor مع Live interface:
‏   - اختر Live interface و lo0 واضغط Start، ثم فعّل Normal browsing وانتظر 10 ثوانٍ.
‏   - اكتب scan في الطرفية، وبعد ثوانٍ يظهر [ALERT] Probe.
‏   - اكتب flood، فيظهر [ALERT] Unknown-Anomaly.
‏   - قل: "المصنف لم يتعلم هذا الهجوم أبداً، والـ Autoencoder هو من كشفه".
‏   - أو فعّل Attack mode ودعه يعمل وحده.
‏6. دقيقة - قسم Lab: اجعل serror_rate تساوي 1 فيصبح القرار DoS.
‏7. دقيقة - القيود بصراحة: Botnet غير مكشوف، والإنذار الكاذب 6% في التقسيم الزمني.

‏قائمة التحقق قبل يوم العرض:
‏[ ] شغّلت الموقع بالطريقة أ وجرّبت كل الأقسام
‏[ ] جرّبت scan و flood في Live وظهرت التنبيهات
‏[ ] اللابتوب مشحون والشاحن معك
‏[ ] أوقفت التحديثات التلقائية والإشعارات (Do Not Disturb)
‏[ ] كل عضو قرأ docs/09_defense_qa.md


================================================================================
‏الجزء 5 - حل المشاكل
================================================================================

‏المشكلة: command not found: netsentinel
‏الحل: أنت لست داخل مجلد المشروع. نفّذ:

$ cd ~/Desktop/netsentinel

‏المشكلة: الصفحة لا تفتح، أو تظهر This site can't be reached
‏الحل: الموقع غير مشغّل. شغّله كما في الجزء 2 واترك Terminal مفتوحاً.

‏المشكلة: address already in use (المنفذ 8000 مشغول)
‏الحل: الموقع يعمل مسبقاً في نافذة أخرى، استخدمها أو أغلقها وشغّل من جديد.
‏أو شغّله على منفذ آخر:

$ sudo .venv/bin/netsentinel web --port 8001

‏المشكلة: زر Live interface لا يعمل (رمادي)
‏الحل: شغّلت الموقع بدون sudo. أوقفه بـ Ctrl+C وشغّله بالطريقة أ.

‏المشكلة: المراقبة تعمل لكن العدادات تبقى 0
‏الحل: تأكد أن الواجهة lo0 مختارة، ثم اكتب scan في الطرفية.

‏المشكلة: nmap is not installed
‏الحل:

$ brew install nmap

‏المشكلة: التحليل بطيء أول مرة
‏الحل: انتظر 10 إلى 20 ثانية أول مرة (يقرأ الملف)، وبعدها يصبح فورياً.

‏المشكلة: أي شيء آخر
‏الحل: أغلق Terminal، وافتح واحداً جديداً، وشغّل الموقع من جديد كما في الجزء 2.


================================================================================
‏الجزء 6 - تحديث المشروع ومشاركة التعديلات (git)
================================================================================

‏يعمل git فقط في مجلد نزّلته بـ git clone، وليس في مجلد منسوخ.
‏ولكي ترفع تعديلاتك، يجب أن يضيفك صاحب المستودع كمشارك.

‏اجلب آخر نسخة من GitHub (قبل أي عمل):

$ git pull

‏احفظ تعديلاتك:

$ git add -A && git commit -m "what changed"

‏ارفعها للفريق:

$ git push

‏الجزء 7 - أوامر متقدمة (للمطورين في الفريق)
================================================================================

‏تشغيل كل الاختبارات (38):
$ .venv/bin/pytest -q

‏تنزيل البيانات (260 MB):
$ .venv/bin/netsentinel download --dataset all

‏تدريب NSL-KDD (حوالي 5 دقائق):
$ .venv/bin/netsentinel train

‏تدريب CIC-IDS2017 (حوالي 20 دقيقة):
$ .venv/bin/netsentinel train --dataset cicids2017

‏تحليل ملف من الطرفية:
$ .venv/bin/netsentinel pcap data/real/real_attack.pcap

‏التقاط حزم حقيقية جديدة:
$ sudo bash tools/capture_real_traffic.sh

‏تعليم النظام شكل الحركة الطبيعية على جهازك:
$ .venv/bin/netsentinel baseline data/real/real_normal.pcap
