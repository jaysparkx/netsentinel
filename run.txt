                    NetSentinel — طريقة التشغيل والاستخدام
================================================================================

كل سطر يبدأ بـ  $  هو أمر: انسخه (بدون علامة $) والصقه في برنامج Terminal ثم Enter.
افتح Terminal على الماك: اضغط  Cmd + Space  واكتب  Terminal  ثم Enter.


================================================================================
 الجزء 1 — التثبيت على لابتوب جديد (مرة واحدة فقط، ~10 دقائق)
================================================================================

(إذا كان المشروع مثبّتاً على اللابتوب مسبقاً، تخطَّ إلى الجزء 2)

1) ثبّت Homebrew (إذا لم يكن مثبّتاً — مدير برامج للماك):
   $ /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

2) ثبّت الأدوات: git و nmap و uv (مدير بايثون سريع):
   $ brew install git nmap uv

3) نزّل المشروع من GitHub (المستودع عام — لا يحتاج حساباً للتنزيل):
   (لكي يرفع العضو تعديلاته، يضيفه صاحب المستودع من:
     https://github.com/jaysparkx/netsentinel/settings/access  ← "Add people")
   $ cd ~/Documents
   $ git clone https://github.com/jaysparkx/netsentinel.git netsentinel
   $ cd netsentinel

4) أنشئ بيئة بايثون وثبّت المكتبات:
   $ uv venv --python 3.11 .venv
   $ uv pip install --python .venv/bin/python -e ".[live,web,dev]"

5) تأكّد أن كل شيء سليم (يجب أن ترى: 38 passed):
   $ .venv/bin/pytest -q

✓ انتهى. النماذج المدرَّبة موجودة داخل المشروع (مجلد artifacts) — لا تحتاج تدريباً.


================================================================================
 الجزء 2 — تشغيل الموقع
================================================================================

ادخل مجلد المشروع أولاً (في كل مرة تفتح Terminal جديداً):
   $ cd ~/Documents/AI-research/netsentinel
   (أو ~/Documents/netsentinel إذا نزّلته من GitHub)

--- الطريقة أ: التشغيل الكامل (مع الكشف الحي) ← هذه للعرض أمام اللجنة ---
   $ sudo .venv/bin/netsentinel web

   • سيطلب "Password:" ← اكتب كلمة مرور الماك (لن تظهر أي حروف وأنت تكتب — طبيعي) ثم Enter.
   • لماذا sudo؟ لأن قراءة كرت الشبكة تحتاج صلاحيات المدير.
   • يفتح المتصفّح تلقائياً على:  http://127.0.0.1:8000

--- الطريقة ب: بدون كلمة مرور (كل شيء ما عدا المراقبة الحية) ---
   $ .venv/bin/netsentinel web

⚠️ مهم جداً:
   • لا تُغلق نافذة Terminal أثناء العرض — إغلاقها يُطفئ الموقع.
   • لا تضغط Ctrl+C داخلها — هذا يُطفئ الموقع أيضاً.
   • لا يحتاج إنترنت إطلاقاً.

للإيقاف في النهاية: اضغط داخل نافذة Terminal ثم  Ctrl + C  (أو أغلق النافذة).


================================================================================
 الجزء 3 — كيف تستخدم الموقع (القائمة في أعلى الصفحة)
================================================================================

[ Tape — الشريط ]
   يعيد تشغيل حزم حقيقية التقطناها من لابتوبنا (تصفّح + nmap + HTTP flood).
   • كل خط عمودي = اتصال واحد.
   • طول الخط = درجة الغرابة (حسب الـ Autoencoder).
   • الخط الأبيض المتقطّع = العتبة. فوقها = غريب.
   • الألوان:  رمادي = طبيعي | برتقالي = مسح/استطلاع | أحمر = هجوم معروف
               سماوي = "شذوذ غير معروف" (هجوم لم يتعلّمه المصنِّف)
   • Capture: اختر الملف.  Speed: السرعة.  Pause: إيقاف مؤقت.

[ How it decides — كيف يقرّر ]
   الخطوات الخمس. الخطوتان 3 و 4 (باللون السماوي) هما تعلّم الآلة.

[ Results — النتائج ]
   • الأزرار في الأعلى = التجارب الأربع. ابدأ بـ "CIC-IDS2017 · temporal" (الأهم).
   • المربّعات: نسبة الكشف، الإنذار الكاذب، الهجمات الجديدة المكشوفة.
     "from X%" = ما كان المصنِّف وحده يحقّقه.
   • بعدها اضغط "CIC-IDS2017 · random" وقارن: 99.7% — واشرح لماذا هذا الرقم مضلِّل.

[ Analyze — تحليل ملف ]
   • اضغط على "real_attack.pcap" ← يظهر التحليل بعد ثانية.
   • أو اسحب أي ملف .pcap من Wireshark إلى المربّع.
   • تظهر "الحوادث": كل حادثة = مهاجم + هدف + نوع هجوم، مع الشرح بالعربية لماذا.

[ Live — العرض الحي ⭐ ] (يحتاج الطريقة أ)
   ثلاثة مفاتيح في الأعلى:
   • Monitoring      = تشغيل/إيقاف المراقبة (NetSentinel يقرأ كل حزمة).
   • Attack mode     = تشغيل/إيقاف الهجوم التلقائي (مسح ← إغراق ← مسح خدمات، يتكرّر).
   • Normal browsing = مستخدم وهمي يتصفّح بشكل طبيعي (حتى يظهر "الطبيعي" على الشاشة).
   يسار الشاشة: Defender = شريط NetSentinel المباشر + العدّادات.
   يمين الشاشة: Attacker = طرفية داخل الموقع. اكتب أمراً واضغط Enter، أو اضغط الأزرار:
       scan          مسح منافذ حقيقي بـ nmap
       service-scan  مسح الخدمات وإصداراتها
       flood         إغراق HTTP (3000 طلب)
       auto on/off   وضع الهجوم التلقائي
       browse on/off التصفّح الطبيعي
       status        ماذا يعمل الآن
       help          قائمة الأوامر
       clear         مسح الشاشة
   🔒 الطرفية لا تقبل إلا هذه الأوامر، وكل الهجمات على هذا اللابتوب فقط (127.0.0.1).
   تنبيهات NetSentinel تظهر داخل الطرفية أيضاً (بخط ملوّن) وتحتها كبطاقات.

[ Lab — المختبر ]
   • اختر نقطة بداية: "اتصال ويب طبيعي" أو "SYN flood" أو "مسح منافذ".
   • حرّك المنزلقات ← القرار يتغيّر فوراً على اليمين، مع السبب.
   • تجربة جميلة للّجنة: من "اتصال طبيعي" ارفع serror_rate إلى 1 و count إلى 300.

 الجزء 5 — حلّ المشاكل
================================================================================

المشكلة: "command not found: netsentinel" أو ".venv/bin/netsentinel: No such file"
   الحل: لست داخل مجلد المشروع:  $ cd ~/Documents/AI-research/netsentinel

المشكلة: الصفحة لا تفتح / "This site can't be reached"
   الحل: الموقع غير مشغّل. شغّله (الجزء 2) واترك Terminal مفتوحاً.

المشكلة: "address already in use" / المنفذ 8000 مشغول
   الحل: الموقع يعمل مسبقاً في نافذة أخرى — استخدمها، أو أغلقها ثم شغّل من جديد.
         أو شغّل على منفذ آخر:  $ sudo .venv/bin/netsentinel web --port 8001

المشكلة: مفتاح Monitoring رمادي لا يعمل
   الحل: شغّلت الموقع بدون sudo. أوقفه (Ctrl+C) وشغّله بالطريقة أ.

المشكلة: Monitoring يعمل لكن العدّاد 0
   الحل: تأكّد أن الواجهة lo0 مختارة، ثم اكتب scan في الطرفية — ستظهر الاتصالات.

المشكلة: "nmap is not installed"
   الحل: $ brew install nmap

المشكلة: الشريط فارغ أول ما يفتح الموقع
   الحل: انتظر 10–20 ثانية في أول تشغيل (يقرأ الملفات). بعدها يصبح فورياً.

المشكلة: أي شيء آخر
   الحل: أغلق Terminal، افتح واحداً جديداً، وشغّل الموقع من جديد (الجزء 2).
